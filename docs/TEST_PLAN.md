# 検証計画

`npm test` でエンジン、候補、履歴、データ選択、保存、GAS公開ディスパッチ、Generatorを確認。`npm run validate` で問題集全件の形式・初期合法性・一意解・正解一致・分類を確認。

## ブラウザ
1. /Sudoku/ で新規起動、4難易度、続きと設定と成績。
2. 入力／候補編集／誤入力／連鎖／1回Undo／Redo／DEL／固定数字保護。
   入力済み1→MEMO9で1・9、Undoで確定1、Redoで1・9。表示ON/OFFと手動・自動確定で確認。
3. ダブルタップ、数字・MEMOの色と文字、関連行列ブロック、同数字。
4. ホームに戻る→続き、リロード→保存復元。新規問題で確認なしに置換しても成績維持。
5. 保存・同期エラー、オフライン再起動、更新通知からの安全な再読込。
6. 390×844、375×667、デスクトップ。横はみ出しなし。盤面正方形、キー44px以上。

## 設定と同期
- 自動入力ON/OFFで新規開始・数字入力・候補除外の連鎖を比較。表示OFFでも有効候補は同じ。設定変更やクラウド取得では盤面・Undo履歴を変更しない。DEL/clearNotes/数字→MEMOは常に連鎖なし。
- 古い保存の初期値・不正な型の正規化、ゲスト/UID別設定、クラウド既存優先・欠落時初期化、別項目同時編集の保持、同じ項目の遅い応答と追加変更、オフライン保存・再読込・再試行、ログイン切替中の古い応答、ローカル保存失敗を確認。
- 途中は変更に対応する単体/UI/エミュレータ検証を選び、全2,000問はエンジン変更を含む最終リリース候補で1回だけ検証する。各担当で重複実行しない。
