# Shared module contract

## Game engine: js/game/engine.js
- `createGame(puzzle, {autoFill=true}={})` returns JSON-serializable game. puzzle: `{puzzleId,difficulty,puzzle}` (81 digit string). `autoFill` must be boolean and is not stored in the game.
- game: `{puzzleId,difficulty,initialBoard:number[81],currentBoard:number[81],manualIncludedCandidates:number[81],manualExcludedCandidates:number[81],sources:string[81],undoStack:[],redoStack:[],elapsedTime:0,startedAt:ISO,lastAutoFilled:number[]}`. Candidate arrays are bitmasks, digit d uses 1 << (d-1).
- `transact(game, {type,cell,value}, {autoFill=true}={})` returns a new game; type `set`, `toggleCandidate`, `delete`, `clearNotes`. Fixed cells are immutable. No-op returns same game. `autoFill:false` suppresses all closure for that action. delete/clearNotes never run auto-fill. clearNotes clears includes and excludes every currently legal candidate for that cell (visible notes become empty in both display modes). toggleCandidate takes optional `autoCandidates` boolean default true, so it toggles the displayed candidate layer correctly. Any explicit exclusion change affects effective candidates. Settings toggles and cloud hydration never transact.
- `undo(game)`, `redo(game)` return new game or same for no-op. Snapshots cover board, candidate masks, sources; not timer. Cap history at 100 steps.
- In-progress `elapsedTime` retains fractional cumulative seconds across pauses, checkpoints and storage reloads. UI and final clear records use whole seconds. Paused time is excluded.
- Deleting a filled editable cell resets both candidate masks for that cell; displayed/effective candidates are recalculated from the current board. Other cells' masks are preserved. Auto-display OFF remains hidden, and deletion never auto-fills even a single candidate. Undo restores the digit and both previous masks together.
- `getLegalCandidates(board,cell)`, `getEffectiveCandidates(game,cell)`, `getDisplayedCandidates(game,cell,autoCandidates=true)` return digit arrays. Effective = legal minus exclusions, regardless of includes/display. Display ON = (legal OR manual included) minus exclusions; OFF = manual included minus exclusions. Illegal manual notes are visible. Filled cells have no displayed notes. Candidate transactions trigger auto-fill only when effective candidates change. `set` rejects a digit already present nine or more times; fixed givens remain immutable.
- `getConflicts(board)` returns array of cell indices; `isComplete(game)` returns boolean.
- createGame performs initial naked-single closure when enabled, outside history. Generator ensures puzzles do not complete automatically at start.

## Data modules owned by root
`js/data/storage.js`: async `loadApp()` returns `{currentGame:null|game,stats,scoreProfiles,settings,settingsProfiles}`; async `saveApp(...)` is atomic. Settings `{autoCandidates:true,autoFill:true,theme:'classic'}`; score aggregates retain `{clearedIds:[],byDifficulty:{},totalClears:0}`, each difficulty value `{clears:0,bestTime:null}`. Re-exports `recordClear(stats,game)` and `emptyStats()` from stats.js, plus `DEFAULT_SETTINGS`. Invalid or missing booleans/themes fall back to defaults without changing the saved game. Legacy selected-account settings migrate to that account, and the guest keeps the original local preferences.
`js/data/puzzle-repository.js`: async `loadPuzzles()` returns puzzle[] using local IndexedDB + bundled fallback; concurrent initial callers share one load, and failed loading remains retryable. Async `syncPuzzles()` returns `{updated,count,offline?}` and cannot be overwritten by a late initial load. `choosePuzzle(puzzles,difficulty,clearedIds=[],currentPuzzleId=null)` returns puzzle or throws. Exclude current if alternative exists, prefer uncleared.
`js/config.js`: constants API_URL, DATASET_VERSION, DIFFICULTIES (Japanese four strings), THEMES (`id,label,color,paper`).
`js/ui/keypad.js`: `getKeypadState(game,cell,mode,autoCandidates=true)` returns nine `{digit,muted,disabled}` items. Memo keys are colored only for currently displayed notes; all nine remain enabled on editable cells regardless of legality. Number keys lose their background and are disabled when the board contains nine or more copies. Fixed givens cannot be edited.
`js/ui/play-feedback.js`: `createPlayFeedback(options={})` returns `{recordInput(previous,next,cell,digit,mode),celebrate(),sync(root,{visible,completionOpen}),cancel()}`. Short-lived UI effects are separate from game and storage state, resume at their original elapsed time after DOM replacement, and respect reduced motion. Only accepted digit/MEMO changes receive input feedback; only a newly completed play receives celebration. No-op, DEL, Undo/Redo, reload and cloud renders do not create new effects.

## Score synchronization
- `js/data/stats.js`: `emptyStats()`, `normalizeStats(stats,puzzles=[])`, `mergeStats(a,b,puzzles=[])`, `recordClear(stats,game)`. Keeps clearedIds/byDifficulty/totalClears and adds per-puzzle `records` plus `legacyBest`. Merge is deduplicating and keeps the minimum known time.
- `js/cloud/firebase-client.js`: lazy Firebase SDK initialization for a named Sudoku app. `createFirebaseClient()` exposes `onAuthStateChanged`, `signIn`, `signOut`, `syncStats(uid,stats)` and a separate settings synchronization API. Score documents contain only score records and legacy difficulty bests; no app snapshot, game, settings, or user email is stored in score documents.
- Firestore paths: `users/{uid}/scores/{puzzleId}` and `users/{uid}/scoreMeta/legacy`. Owner-only rules validate fields and deny all unrelated access. Transactions preserve concurrent record unions and fastest times.
- Local snapshots retain account-separated score and settings profiles alongside the local game. Auth changes preserve the game and switch score/settings profiles. A completion marker prevents replaying a completed game into another profile.

## Settings synchronization
- `js/data/settings-profiles.js` is DOM/network independent. `normalizeSettings`, `isValidSettings`, `validateSettingsPatch` allow only boolean `autoCandidates`/`autoFill` and a known `theme`. Defaults are both booleans true, theme classic.
- `normalizeSettingsProfiles(value,legacySettings,activeKey)`, `selectSettingsProfile(profiles,key)`, `getProfileSettings`, `updateProfileSettings(profiles,key,patch)` keep `{guest,accounts,activeKey}`. Each profile is `{settings,pending,revision}`; pending maps changed field names to positive local revision numbers. New account caches seed only from guest settings, never another account.
- `captureSettingsSync(profiles,uid)` captures `{settings,patch,pending,revision}`. `applySettingsSync(profiles,uid,remote,submitted)` acknowledges only matching sent revisions; newer local fields remain pending and override the reply in the local view.
- `firebaseClient.syncSettings(uid,localSettings,pendingPatch={})` uses a transaction on `users/{uid}/preferences/app`. Exact cloud payload: `{autoCandidates,autoFill,theme}`. Existing cloud fields win unless included in the pending patch; absent cloud data is initialized from localSettings. Different-field edits merge; same-field conflicts use the later successful transaction. No wall-clock ordering guarantee.
- Owner-only rules allow get/create/update on this one preferences document, validate all three fields, and deny lists, deletion, other documents and unrelated fields. All methods guard current auth UID. Startup/login/online/visibility/manual sync retry durable pending changes. Guest settings never upload as edits; they only seed a missing account document.

## Experience
- `stats.experienceEvents`: unique completion UUID keys with immutable `{difficulty}` payloads; absent on old statistics means zero XP (no backfill). Distinct plays of the same puzzle have distinct IDs. Normalize/merge preserve the event union and deduplicate retries.
- `js/data/experience.js`: `getExperience(stats)` returns `{totalExp,level,progress}`; progress is 0..99 and level starts at 1. Rewards are 20/30/40/50 by difficulty.
- `js/data/stats.js`: `awardExperience(stats,eventId,difficulty)` adds one valid completion idempotently.
- `users/{uid}/experience/{eventId}` is owner-only, exact `{difficulty}`, immutable after creation. Game/board never leave the device; preferences use a separate document. XP is derived from completion events, never a last-write-wins total.
- `game.experienceAward` is local completion presentation metadata `{eventId,profileKey,totalExp}`, saved atomically with the game marker and score profile. Startup may restore its result for the matching local profile but must never award XP to a pre-existing completed game.
- `js/data/level-titles.js`: `getLevelTitle(level)` returns display text including 並み, based on the private Levels table; no management identifiers are bundled.

## Generator
`tools/generate-puzzles.mjs` CLI generate deterministic seeded unique puzzles and classify with techniques beyond singles. `tools/validate-puzzles.mjs` validates entire dataset. `data/puzzles.json`: `{schemaVersion:1,datasetVersion:1,puzzles:[{puzzleId,difficulty,puzzle}]}` NO solutions. `.local/puzzles-admin.json` full administrative records including solution, score, seed, generator_version, daily_eligible=false, validated=true, created_at. Need 500 per difficulty if feasible, initially generate 30 each then expand after checks. Classification must not use clue count alone. Tests `tests/generator.test.mjs`. Root writes tools/serve.mjs; generator owns other tools/*.mjs only after coordinating names.

## UI owner
index.html, css/, js/app.js, js/ui/, manifest.webmanifest, icons/, sw.js. Implements full flows with imported modules above. Relative URLs for /Sudoku/. Shell caching and explicit update prompt, no forced reload losing game. Safe-area, dynamic viewport, no zoom suppression outside board. Save state through serialized async storage writer; flush on visibility/pagehide; no timer while background/home/settings. Start new puzzle replaces current without confirmation. Completion stats idempotent. DEL allowed even with conflicts. Settings and stats accessible. Clear user-facing save/sync errors, cached gameplay works.
